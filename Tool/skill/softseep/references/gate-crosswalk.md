# 门禁命名空间交叉映射（Gate Crosswalk）

> **本文件是 Seep 本地新增。**
> 三层技能各自有一套 `G` 开头的门禁，**同名不同义**。不标层前缀就会"自信地满足错误的门"——
> 这正是 `exe-reverse` 的 `O4`（在错误层级打补丁）所警告的失效模式。

---

## 1. 为什么需要这张表

| 门禁 | `softseep`（总控） | `apkseep`（Android） | `exe-reverse`（Windows） |
| :--- | :--- | :--- | :--- |
| **G1** | 样本定性（10 分钟能否判出运行时/壳/子系统） | 交付物形态 | 交付物形态 |
| **G2** | **写入判死归因**（改 1 个无害字符 4s 后是否存活） | 环境真实性 | **主机真实性与能力清单** |
| **G3** | 端点发现（明文 URL / 内存取证） | 代码定位 | 代码定位 |
| **G4** | 响应判定（令牌/时间戳/会话绑定） | 基线对照 | 基线对照 |
| **G5** | — | — | **首次执行前隔离** |

同一个 `G2`，在 softseep 里问"改内存会不会被杀"，在 exe-reverse 里问"这台机器到底支持哪条路线"。
**必须带层前缀。**

---

## 2. 统一前缀约定（硬规则）

| 前缀 | 层 | 序列 | 语义域 |
| :--- | :--- | :--- | :--- |
| **`AUTH-G0…G4`** | `softseep/references/license-validation.md` | G0 权威定性 · G1 样本定性 · G2 写入判死归因 · G3 端点发现 · G4 响应判定 | **许可/激活/卡密类目标的权威归属判定**（决定"能不能测、权威在不在本地"） |
| **`APK-G1…G4`** | `apkseep` | 交付物形态 · 环境真实性 · 代码定位 · 基线对照 | Android 交付纪律 |
| **`EXE-G1…G5`** | `exe-reverse` | 交付物形态 · 主机真实性 · 代码定位 · 基线对照 · **首次执行前隔离** | Windows 交付纪律 |

**引用规则**：
1. 任何提到 `G1…G5` 的地方，必须写清是 `AUTH-` / `APK-` / `EXE-` 哪一层；
2. 未标前缀的裸 `G2` 视为**歧义**，必须澄清后再动作；
3. 三层门禁**叠加生效**，不是替代关系：先 `AUTH-G*`，再平台层 `*-G*`。

## 3. 执行顺序（唯一合法路径）

```
用户输入
   │
   ▼
[AUTH-G0 权威定性]  断网/改时钟/改本地许可文件 → 功能是否仍可用？
   │  纯本地 ⇒ 可继续      需联网 ⇒ 服务器权威，转中继/放弃本地改
   ▼
[平台判型]  Windows / Android / Linux / Web / Flutter
   │
   ├── Windows ──► [EXE-G1 交付物形态]
   │               [EXE-G2 主机真实性]  ← 跑 doctor.py，不许假设
   │               [EXE-G3 代码定位]
   │               [EXE-G4 基线对照]
   │               [EXE-G5 首次执行前隔离]
   │
   └── Android ──► [APK-G1 交付物形态]
                   [APK-G2 环境真实性]
                   [APK-G3 代码定位]
                   [APK-G4 基线对照]
   │
   ▼
[交付与验收]  MANUAL/POC-VALIDATION.md 三阶段闭环
```

## 4. 跨层同名门禁的速查对照

| 你想问的 | 实际该用哪个门 |
| :--- | :--- |
| 改内存会不会触发自毁？ | **`AUTH-G2`**（写入判死归因） |
| 这台机器有没有调试器/IDA/能不能提权？ | **`EXE-G2`**（主机真实性） |
| 交付物到底是补丁、内存补丁、算号器还是报告？ | **`EXE-G1`** 或 **`APK-G1`**（同义） |
| 改之前要不要先做对照运行？ | **`EXE-G4`** / **`APK-G4`** |
| 这个二进制要不要在虚拟机里跑？ | **`EXE-G5`**（只有 Windows 层有） |
| 授权到底谁说了算？ | **`AUTH-G0`** |
| 目标会不会联网校验？ | **`AUTH-G3` + `AUTH-G4`** |

---

## 5. 冲突消解

| 冲突 | 消解 |
| :--- | :--- |
| `AUTH-G2` 说"可继续"，`EXE-G2` 说"没调试器" | 不冲突：前者判**目标**，后者判**主机**。走静态路线或补工具，不是放弃任务 |
| `EXE-G4` 通过但现象没变 | 回到 `EXE-G3`（代码定位错了），**不是**继续打补丁（`O4`） |
| `APK-G2` 与 `EXE-G2` 同时适用（Flutter 双端） | 以**行为实际所在层**为准（Dart AOT ⇒ 原生层，走 `EXE-G2`/`APK-G2` 中对应 ABI 侧） |
| 方法论文件在多个技能里重复 | 允许重复（技能须自包含）；**机制文件才是差异点**，方法论以任一技能内版本为准 |
